## 2026-08-22

**What I worked on**
Added the "Explain this item with AI" feature using GitHub Copilot's Plan → Agent workflow, integrating the Gemini API server-side.

**What I did**
Used Copilot Plan mode to get an initial file-by-file plan, reviewed it critically and sent back 10 specific gaps/clarifications (missing .env.example, ambiguous file naming, Route Handler vs Server Action choice, untrusted-data test case, disabled-state test, beginner-friendly prompt wording, and more). Copilot revised the plan addressing all of them, including switching to a Server Action for consistency with the rest of the app. Delegated the full implementation to Agent mode: server-only Gemini service, allowlisted context builder, server action, and a decomposed client UI (trigger button, explanation card, badge, error display).

**Where I got stuck**
The first working version produced explanations that felt dry and mechanical, and sometimes cut off mid-sentence. Also found the details panel UX was awkward on both mobile (had to scroll past the whole list to see it) and desktop (it stretched the whole page height instead of behaving like a proper sidebar) (still need be improved).

**How I worked through it**
Diagnosed the truncation as a prompt design issue, not a token-limit bug — the prompt was just data with a locale prefix, no real instruction separating tone/intent from the raw facts. Rewrote the prompt to clearly separate instruction from an untrusted-data block, kept maxOutputTokens at 512 as required, and narrowed the sentence count to reduce truncation risk. For the panel UX..it still need improve.

**Decisions made**
Kept the AI feature strictly to allowlisted PokeAPI fields (name, id, types, height, weight, hp, attack) rather than trying to pull anime/lore details from another source — that would require a different, unverified data source and fall outside what the task allows ("public data already provided by the selected public API"). Chose a Server Action over a Route Handler for the Gemini call, for consistency with the rest of the app's existing patterns.

**Open questions**
How can we design a prompt or workflow that makes an AI coding agent explore multiple possible solutions, evaluate their trade-offs, and choose the best one with minimal human intervention?
