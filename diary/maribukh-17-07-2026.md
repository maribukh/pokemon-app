What I worked on

Started the unit testing task. Set up Vitest and RTL, wrote the first tests.

What I did
Configured vitest.config using vitest/config instead of vite, otherwise TS doesn't recognize the test field. Wrote tests for all utils (storage, searchUtils, typeColors, pokemonHelpers), got 100% coverage there right away, the easy part. Wrote tests for Search, Card, CardList, Loader, ErrorMessage.

Where I got stuck
Wasn't sure if I could use a functional component as a test stub (ThrowingChild for testing ErrorBoundary), felt like it broke the "classes only" rule. Also hit a TS error about the JSX.Element namespace, and eslint complained about render() with no return, even though it throws.

How I worked through it

Realized the "classes only" rule applies to actual app components, not test helpers, the stub isn't part of the UI and won't be refactored later. Still made ThrowingChild a class anyway for consistency. Added a targeted eslint-disable comment with an explanation for the render/throw case.

Decisions made
Test stubs (like ThrowingChild) stay as classes for consistency with the rest of the project. All tests go through screen.getByText/getByRole, never touching this.state or instance() directly, so they survive the move to functional components next week.
